### 1. POSIX `credentials_path()` creates `suflyor/`, poisoning `data_root()` away from `overlay-mvp`
- **Finding / Hypothesis:** `posix_credentials::credentials_path()` (`credentials.rs`) always does `dirs::config_dir()?.join("suflyor")` + `ensure_dir_permissions()` → `create_dir_all`. `paths::data_root_in()` then treats **any** existing brand dir as authoritative (`if !brand.exists() && legacy.exists() { legacy } else { brand }`). Credential I/O therefore materializes an empty brand tree and silently orphans a still-populated `overlay-mvp` tree (config, sessions, recordings, keys in `config.json`).
- **Rationale:** Invariant-adjacent data-loss / split-brain: if `migrate_data_root()` failed (file lock, second instance) or has not run yet, the first `credentials::read/write` (e.g. `protected_provider_secret()` from `Config::ai_endpoint()` / `readiness()`) creates `…/suflyor/`. Subsequent `config_path()` / `load()` resolve to the new dir, hit `NotFound`, and return `Config::defaults()`. Live bridge tokens, profiles, and devices remain in `overlay-mvp` while the app writes a fresh `config.json` under `suflyor`. Windows is unaffected (Credential Manager); POSIX/macOS is.
- **Verification Method:** On Linux/macOS, create `~/.config/overlay-mvp/config.json` with a distinctive `ai_bearer` and **do not** create `suflyor`. Skip or fail migration. Call `credentials::read(SecretSlot::OpenAi)` then `config::load()`. Confirm `~/.config/suflyor/` now exists, `data_root()` points at it, and load returns defaults rather than the overlay-mvp bearer. Repeat after a failed `rename(overlay-mvp → suflyor)`.

### 2. `mask_host` keeps query, fragment, and “path-as-authority” bytes (token / LAN IP leaks)
- **Finding / Hypothesis:** `mask_host` (`config.rs`) splits authority only on the first `/`, `?`, or `#`, then emits `format!("{scheme}***{port}{path}")` **verbatim**. It never redacts `path`/`query`/`fragment`. Scheme-relative and extra-slash URLs make the host fall into `path`.
- **Rationale:** Invariant 3 is violated for copyable/loggable strings:
  1. `http://192.168.0.142:18902/v1?token=BRIDGE_SECRET` → `http://***:18902/v1?token=BRIDGE_SECRET`
  2. `http://127.0.0.1/v1#bearer=abc` → fragment preserved
  3. `//192.168.0.142:18902/v1` → `find("://")` fails, `find('/')` is index 0, result `***//192.168.0.142:18902/v1` (LAN IP fully leaked)
  4. `http:///192.168.0.142/v1` → `http://***/192.168.0.142/v1`
  Userinfo (`user:pass@host`) is stripped (good); query-string bridge tokens and the scheme-relative bypass are not.
- **Verification Method:** Unit cases: (a) query `?api_key=` / `?token=`; (b) `#fragment`; (c) `//10.0.0.1:18902/v1`; (d) `http:///10.0.0.1/v1`; (e) `http://u:p@10.0.0.1:18902/v1?x=1` — assert no RFC1918 literal, no `u:p`, no `token=`/`api_key=` values in the returned string.

### 3. Diagnostics `readiness()` embeds unmasked LAN URLs and OS-username paths
- **Finding / Hypothesis:** `Config::readiness()` (`config.rs`) builds UI `detail` with raw `ep.base_url` (`format!("{} · {} · {}", provider, ep.base_url, ep.model)`), raw `stt_gigaam_dir`, and raw `stt_whisper_url`. It never calls `mask_host`. `preview_server_settings()` likewise copies `ai_base_url` / `openai_base_url` / `vision_base_url` / `stt_whisper_url` / `stt_gigaam_dir` into `PreviewGroup` / `gigaam_dir_*` without masking.
- **Rationale:** Invariant 3 names “UI tiles” and exported logs. Default `ai_base_url` is already `http://192.168.0.142:18902/v1`. GigaAM default is `local_ai::gigaam_default_dir(...)` under the user data root (`C:\Users\<user>\…` / `/Users/<user>/…` / `/home/<user>/…`). A diagnostics screenshot, “Собрать логи”, or any log of `ReadinessItem.detail` leaks internal IPs and the OS account name. Comment on `PreviewGroup` even admits LAN IPs are shown and defers to `mask_host` — but the preview path does not use it.
- **Verification Method:** Config with `ai_base_url=http://192.168.55.66:18902/v1`, `stt_provider=gigaam`, `stt_gigaam_dir=/Users/alice/suflyor-local-ai/gigaam-v3`. Call `readiness()` and `preview_server_settings()`. Assert `detail` / `base_url_*` / `gigaam_dir_*` contain `192.168.55.66` and `alice`. Repeat after piping the same structs through the log-export redactor.

### 4. `config.json.bak` is world-readable; `config.json.broken-*` keeps live secrets forever
- **Finding / Hypothesis:** `save_to_path` writes the undo snapshot with `std::fs::write(&bak, redacted)` (no `mode(0o600)`), while the live file is opened with `.mode(0o600)` only on the Unix tmp path. `preserve_corrupt_config` `rename`s the unparseable file to `config.json.broken-<unix_secs>` with **no** `secret_redacted()`, **no** chmod, **no** retention cap.
- **Rationale:** `.bak` is “secret-redacted” in JSON, but `String::clear()` does not zeroize, and the file still contains `meeting_context`, profiles, snippets, and LAN URLs. Default umask `022` → `0644`: any local user who can traverse `~/.config/suflyor` (dir itself is `create_dir_all` **without** `0700`, unlike the credentials dir) can read interview prep. `.broken-*` is worse: it is a full copy of `ai_bearer`, `groq_api_key`, `hermes_bridge_token`, `hermes_api_key`, vision/local bearers — the exact material `secret_redacted` was added to keep out of `.bak`. Repeated parse failures accumulate secret files indefinitely.
- **Verification Method:** POSIX: save a config with a unique `ai_bearer` and `meeting_context`; `stat -c %a config.json.bak` (expect `644` vs `600` on `config.json`); `grep` the bearer (absent) and meeting_context (present). Write truncated JSON, call `load()`, `ls config.json.broken-*` and `grep` the old bearer. Confirm `config_path()`’s directory mode is not `0700`.

### 5. POSIX credentials dir/file TOCTOU and tmp symlink follow
- **Finding / Hypothesis:** `ensure_dir_permissions` is `create_dir_all` then `metadata` then conditional `set_permissions(0o700)` — not `open(O_DIRECTORY|O_NOFOLLOW)` + `fchmod`. `write_to_path` does `path.with_extension("tmp")` (`credentials.json` → **`credentials.tmp`**), `OpenOptions::new().create(true).truncate(true).mode(0o600).open(&tmp)` (follows symlinks), then `rename`.
- **Rationale:** Between `create_dir_all` (umask-typical `0755`) and chmod `0700`, a local attacker who can write the parent can plant `credentials.tmp` → `/tmp/steal` (or a FIFO). `open` follows the symlink, `write_all` dumps the pretty-printed secret map (OpenAI + Anthropic keys) into the attacker’s target; `set_permissions(0o600)` then chmods the **target**. `rename(&tmp, path)` only replaces the symlink inode, so the stolen copy remains. Same class of race as classic mail-spool drops; invariant 2 (“atomically with mode 0600”) holds only on the happy path with a trusted directory.
- **Verification Method:** In a 0777 staging parent: (1) create dir, pause before chmod, inspect mode; (2) `ln -s /tmp/steal credentials.tmp`, call `write_to_path`, read `/tmp/steal` and `stat` its mode; (3) replace `suflyor` with a symlink to a 0777 dir and repeat `ensure_dir_permissions`.

### 6. Direct-provider secrets are copied into owned `String`s with no zeroization (Windows blob included)
- **Finding / Hypothesis:** Windows `read` does `bytes.to_vec()` + `String::from_utf8` then `CredFree` without wiping `CredentialBlob`. Windows `write` zeroizes only the local `blob` via `fill(0)` after `CredWriteW` (not on unwind, not the `CREDENTIALW` copy). POSIX `read_map` / `write` keep a `HashMap<String, String>` and `cloned()` values. `protected_provider_secret` returns that `String` into `AiEndpoint.bearer` on every `ai_endpoint()` / `vision_endpoint()` / `readiness()` call. `secret_redacted` `clone()`s the whole `Config` then `clear()`s secret fields (capacity retained, plaintext left in the clone’s buffers until drop).
- **Rationale:** Invariant 1 is about serialization, but the same keys are specified as never entering logs/exports; heap residue + `FromUtf8Error` (on invalid UTF-8, the error object **owns** the secret bytes until `context(...)` drops it) is the residual disclosure path for crash dumps, swap, and debug allocators. `readiness()` loads the live key solely to test `!ep.bearer.trim().is_empty()` — a presence check that does not need a heap copy of the secret.
- **Verification Method:** (Windows) breakpoint after `from_utf8` / after `CredFree`; search process memory for the test key. Force non-UTF-8 blob and inspect `FromUtf8Error` contents. (POSIX) `write` two slots, `read` one, heap-dump. Call `secret_redacted` under a custom allocator and assert the clone buffer is wiped, not merely `len==0`. Replace presence checks with a `exists()` API that never materializes the secret.

### 7. POSIX credentials RMW is non-atomic: corrupt JSON or concurrent writers drop the other slot
- **Finding / Hypothesis:** `write`/`delete` do `read_map()` → mutate one key → `write_map()`. `read_map` on missing/unreadable/invalid JSON returns `HashMap::new()` (`unwrap_or_default()`), not an error. There is no file lock, `O_EXCL`, or merge.
- **Rationale:** Two writers (UI save OpenAI, background save Anthropic) each read a one-key map and the last `rename` wins — the other direct-provider key is deleted from disk. A truncated `credentials.json` (crash between write and fsync; there is **no** `sync_all`) is treated as empty, so the next successful `write(OpenAi)` persists only OpenAI and **erases** Anthropic. Fail-open empty map is a credential-destruction bug that also encourages users to paste keys back into less-protected surfaces.
- **Verification Method:** Write both slots. Truncate `credentials.json` to `{`. Call `write(SecretSlot::OpenAi, "k1")`. Parse file: Anthropic key must still be present (today it is not). Concurrent test: two threads writing different slots; both keys must remain.

### 8. `import_server_settings_from` clobbers machine-local `stt_gigaam_dir` (path / username / traversal)
- **Finding / Hypothesis:** `merge_server_settings` copies `imported.stt_gigaam_dir` (and `stt_gigaam_gpu`) onto `current`. `import_server_settings_from` saves that merge directly. `apply_server_settings` (the documented UI Apply path) explicitly **reverts** `stt_gigaam_dir` because it is a path on this PC. Preview even surfaces `gigaam_dir_incoming` as “NOT applied”.
- **Rationale:** The non-preview import is a bypass: a portable “server settings” file from another machine (or a malicious JSON) overwrites the model directory with `C:\Users\other\…` or `../../.ssh` / UNC paths. That leaks the source username into this install’s `config.json` and, if STT later opens files under that dir, becomes a stored-path traversal. Direct-provider keys stay out of `Config`, but this is a settings-wipe + privacy leak in the same repair/import surface.
- **Verification Method:** `current.stt_gigaam_dir = "/opt/gigaam"`; imported JSON `"stt_gigaam_dir": "/Users/victim/secret"`. Compare `import_server_settings_from` vs `apply_server_settings`. Assert only the latter preserves `/opt/gigaam`. Add a `../` payload and trace any subsequent model-file open.

### 9. Load/save error paths log filesystem paths (OS username) and default-write can persist a wiped config
- **Finding / Hypothesis:** `config_path()` uses `.with_context(|| format!("create config dir {}", dir.display()))`. `load()` logs `config dir unavailable ({e})`, `config read failed ({e})`, and `preserved corrupt config as {}` with `backup.display()`. `data_root()` is `%APPDATA%\<user>\…` / `$HOME/…`. After parse failure, `preserve_corrupt_config` + `Config::defaults()`; if any migration sets `dirty`, `save(&cfg)` writes **defaults** over the canonical path.
- **Rationale:** `http_log.rs` correctly refuses body text, but config I/O still puts `C:\Users\alice\AppData\Roaming\suflyor\config.json.broken-…` into `overlay-host.log` / exported `suflyor-log.txt`. A single corrupt byte plus a successful migration save (TTS/vision/gigaam/version stamp) replaces the user’s file with defaults (bearers empty, default LAN `ai_base_url` restored). The secrets survive only in unredacted `.broken-*` (Finding 4), not in the live app.
- **Verification Method:** Trigger `create_dir_all` failure and a `NotFound` vs `PermissionDenied` read; grep the log for the home/user segment. Place invalid JSON with a real `ai_bearer`, call `load()` on a build where a migration sets `dirty` (e.g. empty TTS fields or `config_version: 0`); confirm new `config.json` is defaults and the log line contains the username path.

### 10. `http_error_line` is safe in isolation; `op` is an unsanitized injection point
- **Finding / Hypothesis:** `http_error_line(op, status, body_len)` (`http_log.rs`) interpolates `op` with no host/userinfo/query stripping and never receives the URL or body. Callers outside this file that pass `format!("{url}")` or status-text into `op` reintroduce the P0-1 leak this helper was written to stop.
- **Rationale:** Invariant 3 is only as strong as the call sites. The helper’s tests prove the **body** cannot leak through `body_len`; they do not prove `op` cannot contain `http://user:BRIDGE@192.168.0.142/v1?key=`. Combined with Finding 2, a caller that “masks” then concatenates still ships query tokens.
- **Verification Method:** `rg http_error_line` across the crate; assert every `op` is a string literal (`"AI complete"`, `"STT"`). Add a negative test: `http_error_line("http://u:p@10.0.0.1/v1?token=s", 500, 3)` must not be considered an acceptable production `op` (lint or allowlist).
