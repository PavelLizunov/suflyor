# Audio route/settings/metrics/watchdog: bounded source contract

**Baseline:** `a10c356af05a5832a14ea06a5d0cb6c49694e3f1`. Selected route policy/WASAPI worker/Settings/macOS metrics/watchdog source plus Rust test intent. **No device enumeration/capture, COM callbacks, user config read/write, session restart, Rust/native/UI/audio/performance execution**. Config selection, frames enqueued, native capture alive and successful STT are different states.

## Windows device identity and notification policy

[Device enumeration/name match](<../../../overlay-backend/src/audio.rs#L88-L138>) Render/Capture friendly names, duplicates logged; pinned friendly-name lookup returns first exact match, no stable endpoint-id persisted. [DeviceSelection](<../../../overlay-backend/src/audio_route.rs#L15-L41>) blank/None follows default, nonblank pinned; trim used only emptiness, not normalization saved name. [RecoveryPolicy](<../../../overlay-backend/src/audio_route.rs#L116-L170>) default-change reopens only FollowDefault + matching selected flow/eConsole/changed endpoint, pinned ignores default switch; matching endpoint state/removal/format reopens.

[IMM notification callback](<../../../overlay-backend/src/audio_route.rs#L189-L259>) converts endpoint id and publishes native-event queue, only specific engine-format property; added/device-name properties no-op. Null default endpoint id **dropped** instead of scheduling MissingEndpoint, so no-default transition relies on capture failure/other notification; not tested unplug scenario. [RouteWatcher](<../../../overlay-backend/src/audio_route.rs#L265-L310>) CoCreateEnumerator register callback, drains try_recv, Drop unregister best effort. COM apartment/callback lifetime/volume/race no native acceptance.

## WASAPI reopen/retry, queue loss and handle lifetime

[Capture start/Drop](<../../../overlay-backend/src/audio.rs#L141-L199>) detached worker threads, own COM init, handle Drop sets stop flag **does not join**. Start returns before native device open; source startup errors logged, no synchronous success proof. [Recovery loop](<../../../overlay-backend/src/audio.rs#L203-L266>) loops until stop, RecoveryRequested/Err increments saturating attempt, fixed1s wait, no attempt budget/backoff ceiling. Persistent failure can loop until stopped; normal disconnected stream doesn't automatically make UI truthful.

[Endpoint selection](<../../../overlay-backend/src/audio.rs#L279-L339>) Mic Capture; pinned System tries Render then Capture, default System Render. Missing pinned fails/retries, **doesn't silently switch default**. [Native open/loop](<../../../overlay-backend/src/audio.rs#L340-L438>) real endpoint-id/format/role build, watcher failure logged then capture continues without notifications; test async event wait200ms used to drain route and poll stop. Event timeouts silently continue, not treat prolonged no-frames as recovery. Format errors/native capture failure requests reopen, actual device silent/hang outcomes untested.

[Drain/downmix/feed](<../../../overlay-backend/src/audio.rs#L440-L495>) deinterleaves/downmixes PCM, resamples to16k, accumulates3200sample/~200ms chunks, try_send drops full queue without blocking and clears only on stop/disconnect. Timestamp worker-origin elapsed maintained across reopens. Native device-rate change/phase reset/COM control lifetime/missing silence flags and short data branch correctness not fully numerical-tested here.

## Metrics are successful Rust enqueue, not audio signal/device-only liveness

[AudioMetrics](<../../../overlay-backend/src/audio_metrics.rs#L23-L117>) per-stream Mutex saturating counters, Rust pending high-water mark (not native ring), sequential two-stream snapshot **not atomic across both**. [Mic try_send](<../../../overlay-backend/src/audio_macos.rs#L797-L825>) / [System](<../../../overlay-backend/src/audio_macos.rs#L940-L969>) emitted counter increments only successful enqueue, queue-full increments drop, closed exits; native ring overflow separate counter. This matters watchdog: downstream queue stall can stop emission while native ring/device still capture. No claim counters prove end-to-end useful text or acoustic activity; silent samples still chunks.

## macOS watchdog one-shot post-first-flow stop

[Pure policy](<../../../slint-experiment/src/bin/overlay_host/capture_watchdog.rs#L3-L91>)2s tick, each stream becomes expected only after first nonzero emitted count. Five stagnant ticks after that (~10s at ideal scheduling) or missing capture snapshot when expected requests one stop. Never-flowed/permission-missing streams don't stop, other stream moving doesn't hide stalled expected stream. No unpause/mute condition fed policy; emitted chunks independent capture-gating so pause/mute may still flow under prior capture contract, pending or full queue remains separate.

[Host timer](<../../../slint-experiment/src/bin/overlay_host_windows.rs#L1743-L1868>) checks intended timer, gets emitted pair, one-shot pending latch, immediately resets app/UI timer/status, increments intent generation, async acquires lifecycle and checks stop-intent/current stopped state before stop/debrief. Stops session, error tile notice, **never auto restarts**; skipped stale operation clears latch only. Native consent/coreaudio/queue-block scheduling/formatted-state acceptance open. [Guard tests](<../../../slint-experiment/tests/macos_capture_watchdog_guard.rs#L13-L81>) verify source timer/mic-system stop/error/lifecycle; [policy examples](<../../../slint-experiment/src/bin/overlay_host/capture_watchdog.rs#L94-L155>) synthetic counts, no capture process or native tests executed here.
