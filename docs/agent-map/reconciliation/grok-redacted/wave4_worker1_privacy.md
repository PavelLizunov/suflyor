### 1. Log sanitization — home/username forms
- **Finding / Hypothesis:** `redact_home_all_forms` / `redact_home_in` (`diagnostics.rs`) only substitute the literal `USERPROFILE`/`HOME`/`dirs::home_dir()` string in three separator spellings (raw, `\\` doubled, `/`). They never redact the username token itself, 8.3 short names, or drive-less/`HOMEPATH` tails. The 8.3 gap is even documented as a “conscious residual” on `redact_home_all_forms`.
- **Rationale:** Invariant is “exported logs must NEVER leak OS usernames / local user paths.” A tester posting `suflyor-log.txt` still leaks identity when the log contains `ALICE~1`, `COMPUTER\alice`, `USER=alice`, `\Users\alice\...` (no `C:`), mixed separators (`C:\Users/alice`), WSL `/mnt/c~` when `HOME` is the Windows path, or any path not prefixed by the env home (e.g. `D:\alice\models`). `\\?\%USERPROFILE%` *does* substring-match and is OK; 8.3 and bare username are not.
- **Verification Method:** Set `USERPROFILE=%USERPROFILE% Smith`, synthesize a log with `%USERPROFILE%~1\suflyor-local-ai`, `running as Alice Smith`, and `HOMEPATH=\Users\Alice Smith`. Call `collect_redacted_log` / `redact_user_home` and assert the username and 8.3 token are absent (today they remain).

### 2. Log sanitization — `redact_urls` host-only; query/userinfo/non-http bypass
- **Finding / Hypothesis:** `redact_urls` only finds case-insensitive `http://` / `https://` runs up to ASCII whitespace, then calls `mask_host`. Tests show userinfo in *http(s)* URLs is collapsed to `***`, but (a) query/fragment are kept with the path, (b) non-http URLs are untouched, (c) scheme-less hosts/IPv6 are not URLs. `redact_ipv4` is dotted-quad only. `collect_redacted_log` applies `redact_urls` → `redact_ipv4` → `redact_user_home` → `redact_secrets` (order differs from `build_diag_report`).
- **Rationale:** Support paste of `https://api.example.com/v1?api_key=...&access_token=...` or `https://host/oauth?code=...` keeps secrets in the query. `Bearer%20` / `token=` in query never matches `redact_secrets`’s `"Bearer "` literal. `ftp://user:pass@<private-ip>`, `postgres://`, `ws://`, `file://` leak userinfo; only the IPv4 (if any) is replaced. Bare `<private-host>:18902`, `<private-host>`, and `[<private-ipv6>]` / `<private-ipv6-prefix>` LAN addresses survive both passes — a DNS/IPv6 LAN leak the comments claim is in-scope.
- **Verification Method:** Feed `collect_redacted_log`’s pipeline: `https://x/v1?api_key=secret`, `HTTP://user:pass@h/v1` (already tested), `ftp://user:pass@<private-ip>`, `wss://<private-host>/v1`, `ready @ <private-host>:18902`, `listen [<private-ipv6>]:9`. Confirm query/userinfo/DNS/IPv6 are still present after `redact_secrets(&redact_user_home(&redact_ipv4(&redact_urls(raw))))`.

### 3. Secret token redaction — missing prefixes and brittle matching
- **Finding / Hypothesis:** `redact_secrets` only matches exact `"Bearer "` (capital B, single 0x20), `"gsk_"`, and `"sk-"` with an alnum/`_` lookbehind. There is no `ghp_` / `gho_` / `github_pat_` / `ANTHROPIC_API_KEY` / `hf_` / `xai-` handling. `BEARER`, `bearer`, `Bearer\t`, `Bearer:`, and `Bearer  ` (two spaces) miss. Double-space is a skip bug: after consuming `"Bearer "`, `find(char::is_whitespace)` returns 0, so the real token is left in `rest`.
- **Rationale:** GitHub PATs (`ghp_…`) and env dumps (`ANTHROPIC_API_KEY=…` without an `sk-` value, or values wrapped in quotes/newlines) go into `suflyor-log.txt` verbatim. Uppercase `Authorization: BEARER …` (common in debug dumps) bypasses. Adjacent punctuation is mostly absorbed into the token (over-redact, OK), but JSON `"Bearer":"sk-…"` still relies on the `sk-` branch; a non-`sk-` bearer JSON field leaks. `gsk_` has **no** lookbehind (`foogsk_secret` over-redacts; not a leak). Anthropic `sk-ant-…` is covered only if `sk-` appears at a non-alnum boundary.
- **Verification Method:** Unit-test `redact_secrets` on `BEARER abc`, `Bearer  abc` (two spaces), `Bearer\tabc`, `ghp_deadbeef`, `ANTHROPIC_API_KEY=plain`, `Authorization: Basic dXNlcjpwYXNz`. Current tests only cover `Bearer ` / `gsk_` / `sk-proj-` / `desk-1`.

### 4. Screen capture — no temp raw dump in this module; unbounded RAM + weak converter
- **Finding / Hypothesis:** `vision_capture.rs` does not `write` BGRA to temp or `diag!` pixel payloads. The freeze lives in RAM: `capture_virtual_desktop` → `bgra_to_slint_image` (`set_frozen`) **and** `Rc` of the full `CapturedBgra` captured into persistent overlay callbacks (`on_region_selected`). That Rc is only replaced on the next F8. `bgra_to_slint_image` does `SharedPixelBuffer::new(w, h)` then copies `bgra.as_chunks::<4>()` with a `get_mut` guard; it does **not** assert `bgra.len() == w*h*4` and uses raw `fw, fh` (window size uses `.max(1)`, the image path does not). Encode is in-memory JPEG data-URL; journal stores `attached_screenshot: true` plus prompts, not the bitmap, but `PttStreamSink` seeds the convo with the data-URL.
- **Rationale:** Uncompressed multi-monitor frames (tens–hundreds of MB) remain in the stealthed overlay + callback closures after cancel — visual memory is not bounded to the crop. No evidence in this file of temp raw bitmaps; residual risk is conversation/journal persistence of JPEG base64 (out of file but on the same path). Malformed capture (`w,h` huge or 0, length mismatch) will not panic in the copy loop, but `SharedPixelBuffer::new(u32::MAX, …)` / 0×0 can OOM-abort or trip Slint; that is an availability bug on a garbage capture header, not a disk leak.
- **Verification Method:** (1) F8, Esc, dump process working set / hold a weaks on the overlay image — frame still resident until next F8. (2) Call `bgra_to_slint_image(&[], 0, 0)` and `bgra_to_slint_image(&[0;3], 1, 1)` and a `w=65535,h=65535` stub. (3) Grep `launch_vision_for_bgra` / `bgra_to_jpeg_data_url` for `std::fs` / `%TEMP%` (absent here). (4) Confirm `overlay-host.log` after F8 contains only `origin=` / `encode failed:` strings, not BGRA.

### 5. Read-aloud / clipboard — no history scrape; no scrub before store/speak/export
- **Finding / Hypothesis:** `read_aloud.rs` never reads clipboard history APIs. `restore_text_clipboard` writes back a single saved UTF-8 snapshot (or clears). `spawn_text_tile` / `fill_ocr_tile` store the **full** selection/OCR string in `bridge.store_conversation` and call `speak_explicit` with no `redact_secrets`. This file only `diag!`s modifier timeout, not payload. `LAST_CLOSED_READ_TILE` retains the previous tile (and thus text) after close.
- **Rationale:** Accidental Shift+Alt+1 still surfaces whatever was selected (password manager, bearer, bank page) in a tile, TTS, and the conversation map; OCR (Ctrl+F8) does the same for on-screen secrets. That is product behavior, but if any later journal/`eprintln` dumps user turns into `overlay-host.log`, `collect_redacted_log` will only catch `Bearer `/`gsk_`/`sk-` — clipboard passwords and `ghp_` leak into the public bundle. History is not walked; the leak is current selection + retained last tile, not the OS clipboard ring.
- **Verification Method:** Put `ghp_notareal` / `password: hunter2` on the clipboard/selection, fire SA1, then (a) confirm tile + convo store contain the raw string, (b) grep `overlay-host.log` and `suflyor-log.txt` for it, (c) confirm `restore_text_clipboard` does not log `saved`, (d) close the tile and assert `LAST_CLOSED_READ_TILE` still holds the secret until replaced.
