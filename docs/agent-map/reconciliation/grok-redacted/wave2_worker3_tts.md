### 1. Stdio Buffer & Line Caps
- **Finding / Hypothesis:** There is **no SPEAK size cap** on either side. `Tts::speak` base64-encodes the entire cleaned document and writes it as **one** `SPEAK <b64>` line while holding the sidecar mutex (`overlay-backend/src/tts.rs` `Tts::speak` → `format!("SPEAK {b64}")` → `Sidecar::write_raw` `writeln!(si, "{line}").and_then(|_| si.flush())`). Sidecars ingest with unbounded `stdin.lock().lines()` (`suflyor-tts/src/main.rs` stdin thread; `suflyor-teratts/src/main.rs` same). `BufRead::lines()` grows a single `String` until `\n`. Piper then `STANDARD.decode` + `String::from_utf8` in `parse_cmd`; Tera does the same in `protocol::parse_cmd`. Host-side chunking does not exist; sidecar chunking (`engine::text::MAX_CHUNK_CHARS = 350` / Tera `chunk::chunk_text`) happens **after** the full payload is in RAM.
- **Rationale:** A large OCR dump (tens of MB) becomes ~4/3 that size on the wire. Windows anonymous pipes are typically 4KiB (≤64KiB). `write_raw` is synchronous and runs under `Arc<Mutex<Sidecar>>` plus the process-global `GLOBAL` TTS mutex (`with()`). If `speak()` is on the UI/event thread, the host **stalls for the entire pipe drain**. The sidecar stdin thread must allocate the full line + decoded UTF-8 + chunk `VecDeque`. Tera then **enqueues every chunk** on an unbounded `mpsc` (`Controller::speak` loop over `dispatch.dispatch`). Piper keeps all chunks in `pending: VecDeque<String>` and `Playback::feed`s PCM with no visible backpressure in this tree. Failure sequence: huge `SPEAK` → UI freeze on `WriteFile`/`write` → sidecar RSS spike → OOM kill → host `write_raw` fails or the next `ensure()` counts a crash. There is no `MAX_SPEAK_BYTES`, no chunked `SPEAK` framing, and no incremental stdin protocol.
- **Verification Method:** Drive `speak()` with a 5–20MB repeated-text fixture (no markdown so `to_speech` does not shrink it). Instrument time spent inside `write_raw` and sidecar RSS. Confirm a single stdin `lines()` allocation via a debugger break in `parse_cmd` / `protocol::parse_cmd` before `chunk_text`. Repeat with the pipe reader delayed (breakpoint in sidecar stdin thread) and watch the host UI thread block. Add a unit/integration test that rejects or splits payloads over a fixed cap (e.g. 64KiB decoded).

### 2. Pipe Deadlocks
- **Finding / Hypothesis:** Classic parent-write/child-write deadlock is **mostly mitigated** by a dedicated host stdout reader (`Sidecar::ensure` status thread + `BufReader::lines`) and sidecar stdin thread, with stderr diverted to a log file or `Stdio::null()` (`sidecar_stderr`). Residual deadlock/stall bugs: (a) status-thread spawn is **ignored** (`let _ = std::thread::Builder::new()...spawn(...)` in `Sidecar::ensure`) — if spawn fails, `ChildStdout` is dropped and the pipe closes, but a partial-failure path that left stdout unconsumed would freeze the sidecar on `writeln!(stdout)`; (b) `write_raw` can still **block forever** on a stuck sidecar stdin reader while holding both TTS mutexes, so `pause`/`stop`/`speak` cannot run; (c) Piper `eprintln!` diagnostics and Tera `eprintln!` on a full/locked `%APPDATA%\suflyor\*.log` can block the **worker** (Piper synthesizes on that same thread). Unbounded host←sidecar event volume is low (READY/STARTED/PLAYING/DONE/FAILED), so stdout fill is unlikely **if** the status thread is alive.
- **Rationale:** Deadlock recipe: host blocked in `writeln` of a multi-MB `SPEAK` (pipe full) **and** sidecar blocked in `writeln` of status because nobody is reading stdout. The dedicated reader prevents this unless it never starts or has already exited. Piper’s worker, when `pending` is empty, `recv()`s; when synthesizing it `try_recv`s — stdin can still be consumed. Tera’s protocol loop is separate from `synth_worker`, which is better. The serious production issue is **lock-extended blocking writes**: `stop()` must acquire the same `Mutex<Sidecar>` to `send_if_alive("STOP")`. A hung huge `SPEAK` write makes STOP undeliverable; the tile stays “speaking” until `until_ms` / watchdog. Stderr-to-file is the right idea; it is not bounded or non-blocking.
- **Verification Method:** (1) Fail `thread::Builder::spawn` with a test double / `ulimit -u` and confirm sidecar `READY`/`STARTED` blocks. (2) Pause the status thread (`piper-status` / `teratts-status`) in a debugger, then `speak()` a large payload and a `STOP` from another call — expect STOP to wait on the sidecar mutex. (3) Fill the disk or `flock` the log file and issue rapid `SPEAK`s; watch Piper worker stall in `eprintln` while stdin still drains. (4) Assert spawn failure is fatal or retries, and that `write_raw` uses a timeout or is moved off the UI/`GLOBAL` lock.

### 3. Process Cleanup & Zombies
- **Finding / Hypothesis:** Windows-only lifetime job: `spawn_engine_sidecar` calls `crate::local_ai::assign_to_lifetime_job(&proc)` under `#[cfg(windows)]` only. **No POSIX death signal**, no `PR_SET_PDEATHSIG`, no process-group `killpg`, no `Command::kill_on_drop`. `Sidecar` has **no `Drop` that `kill()`s/`wait()`s**. The process-global `OnceLock<Mutex<Tts>>` is never dropped at exit. Cleanup is “stdin EOF → sidecar `Shutdown`/`close_active()`” (`suflyor-tts` worker end; Tera `worker()`). `ensure()` uses `try_wait()`; if the child is dead it drops `Child` after reap (`Ok(Some(_))` is fine). If `try_wait` errors, `proc = None` drops an unreaped `Child` → **Unix zombie**. Piper crash counter never gates `crashed_out()` for Piper (only Tera `TERA_CRASH_LIMIT`), so a crashing Piper can be respawned forever. JobObject behavior is **not in this diff**; if `assign_to_lifetime_job` is not `KILL_ON_JOB_CLOSE`, `TerminateProcess` on the host can leave `suflyor-tts.exe` speaking (the tester bug the sidecar comments claim to fix).
- **Rationale:** Stdin-EOF works for graceful host exit and most `kill -9` cases because the OS closes the pipe. It **fails** when: the sidecar is a grandchild not sharing the job; the host process is frozen but not exited (sidecars keep talking); Piper is blocked inside `OfflineTts::generate_with_config` so `Message::Shutdown` sits on `rx` until the chunk finishes — speech continues after the UI is gone. Tera is better: protocol thread `close_active()` on `Shutdown` without waiting for synth. Orphaned children after a host crash without JobObject = continued audio + leaked ONNX processes. Tests that drop `Tts` leak children until pipes close; `Child` drop does not kill.
- **Verification Method:** Windows: spawn TTS, `taskkill /F` the host, confirm both `suflyor-tts.exe` and `suflyor-teratts.exe` die (Process Explorer job membership + `KILL_ON_JOB_CLOSE`). macOS/Linux: same with `kill -9 $host`; confirm no leftover sidecar and no zombies (`ps -el | grep Z`). Break in Piper `e.synth()` and close host stdin — audio should still finish the chunk. Add `Drop for Sidecar { kill + wait }` and POSIX `PDEATHSIG`/`kill_on_drop`. Inspect `assign_to_lifetime_job` for `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and assignment **before** the child runs user code.

### 4. Protocol Desynchronization
- **Finding / Hypothesis:** `PlaybackTracker` is a **FIFO** (`pending: VecDeque` + `started()` = `pop_front()`) (`overlay-backend/src/tts.rs`). Host **registers the generation before the write** (`send_piper_speak` / `send_tera_speak`). Piper **silently drops** unparsable lines (`if let Some(cmd) = parse_cmd(&line)` else ignore) and **never emits `REJECTED`**. Tera emits `REJECTED`, but host `rejected()` only pops pending for `invalid-base64` | `invalid-utf8`. Therefore: write succeeds + sidecar drops SPEAK → pending head is a ghost. The next real `STARTED id=N` is bound to the **wrong** host generation. `clear_speaking_generation` then no-ops (`active_generation != generation`), so the live utterance is never cleared by `DONE`; STT suppression falls back to the generous `until_ms` estimate / `arm_terminal_watchdog` (armed on the **mis-attributed** STARTED). `stop_generation` can cancel the *current* gen, but the sidecar id map remains skewed. Piper `VOICE`/`STOP`/`SPEAK` interrupt emits `DONE` for the old id then `STARTED` for the new — that is ordered, but a prior ghost pending still steals the new `STARTED`. Malformed host status lines are ignored (`parse_playback_event` `Err` → warn), which is safe; **missing** events are not.
- **Rationale:** Failure sequence: (1) `SPEAK` with truncated/invalid base64 that still left the host (or a future host bug, or a mid-line write cut by a crash/restart). Piper `parse_cmd` returns `None`. (2) Host `pending = [G1]`, `active_generation = G1`, `is_speaking() == true`. (3) User speaks again: `pending = [G1, G2]`, active = G2. (4) Sidecar `STARTED id=1` for the second utterance → tracker maps `1 → G1`. (5) `DONE id=1` → `finish_generation(G1)` does not clear G2. Tile/STT stay wrong until the estimate expires, while audio is already done — or the reverse if watchdog was armed on the stolen STARTED. Tera is tighter (explicit `REJECTED`, PLAYING, one terminal per STARTED in `Controller`), but host FIFO still assumes **every successful `write_raw(SPEAK)` produces exactly one STARTED**. There is no SPEAK sequence number on the wire; ids are sidecar-local and remapped only by order. `handle_playback_eof` drains the tracker for that process, which heals a dead sidecar, not a live desync.
- **Verification Method:** Patch Piper `parse_cmd` to drop one valid `SPEAK` (or send `SPEAK ***` after a successful host write). Call `speak("one")` then `speak("two")`. Assert `STARTED id=1` must attach to generation 2, not 1; today `PlaybackTracker::started` will bind id 1 to gen 1. Check `is_speaking()` / `should_suppress_stt()` after the real `DONE`. Repeat with Tera `REJECTED reason=unknown-voice` vs `invalid-base64`. Fix: put `id=` or `gen=` on `SPEAK`, or require sidecar `ACK`/`REJECTED` for every SPEAK; treat unmatched STARTED as fatal resync (drain + stop). Add a test that a silent drop cannot steal the next STARTED.

### Cross-cutting notes (same IPC surface)
- **Command injection on control lines:** Host interpolates unsanitized voice/lang into `VOICE {id}` / `LANG {lang}` (`set_voice`, `ensure`). A newline in a config/dir name splits stdin commands. Sidecar Piper validates voice **path** (`is_valid_voice_dir`) but the **line split already happened**. Verify with `tts_voice = "irina\\nSTOP"`.
- **ONNX isolation invariant holds at process boundary:** GigaAM stays in-host; Piper ONNX in `suflyor-tts.exe`; Tera `ort` in `suflyor-teratts.exe`. Diarization is a separate invocation of `suflyor-tts diarize` (`main.rs` argv dispatch). Do not merge those processes.
- **Highest practical severity:** unbounded one-line `SPEAK` (UI freeze + OOM) and Piper silent-drop FIFO desync. JobObject/POSIX kill is the lifecycle hole that already shipped as “speech continues after app close.”
