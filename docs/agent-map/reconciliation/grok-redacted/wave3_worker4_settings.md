### 1. Reused-window path does not reseed persistent controls (coaching / retention / profiles after import)
- **Finding / Hypothesis:** `SettingsWindow` is only reconstructed after `on_close_clicked` drops the slot (`settings_controller.rs`, `*settings_close.borrow_mut() = None`). The still-alive reuse path (`open_settings` when `settings_slot` is `Some`) calls `populate_token_status` + `refresh_profiles` + `populate_component_rows`, but the first-open-only block that seeds `coaching_debrief`, `coaching_live_tiles`, `record_audio`, `auto_tiles_enabled`, `suppress_tiles`, `trigger_keywords_input`, `retention_mode` / `retention_value`, `journal_keep_value` / `journal_mb_value`, and `always_on_top_toggle` is skipped. Worse: full-profile import (`on_import_profile_clicked`) assigns `*cfg_c.write() = imported` then `msg_refresh_after_import()` → **only** `populate_token_status()`. It never calls `refresh_profiles()` and never reseeds those toggles.
- **Rationale:** After Import (or F8 hide/reveal while another path mutated `cfg`), the AI/token widgets look updated while Profile / Coaching / Auto-tiles / retention still show the pre-import values. That is a direct UI lie on the singleton, and it contradicts “restart for full effect” because *some* fields *do* refresh. `meeting_context_input` / profile picker stay stale until the window is destroyed.
- **Verification Method:** Open Settings → note coaching/retention/profile editor → Import a JSON with different `post_meeting_debrief_enabled`, `record_retention_days`, `meeting_context`, `context_profiles` → observe token status update and those controls not. Repeat with F8 hide/show without clicking Close.

### 2. Transient install / updater flags are force-cleared while workers still run
- **Finding / Hypothesis:** `populate_token_status()` blindly does `set_ocr_installing(false)`, `set_tts_installing(false)`, `set_tera_installing(false)`, `set_diar_installing(false)`, `set_update_checking(false)`, `set_update_available(false)`, plus `reset_component_install_state` / `set_component_busy_*`. GigaAM is the *only* installer that guards with `if !win.get_stt_gigaam_installing()`. Component install callbacks have **no generation token** (unlike Tera / Codex): a worker can still `set_component_busy_phase(8)` after reopen reset.
- **Rationale:** F8 / gear-reuse mid-download paints “idle / not installing / no update”, so the user can start a second install or think a download finished. A late failure callback then shows a generic error on a row that is no longer busy. Classic reused-window stale-status class, just inverted: you clear live work, not only old strings.
- **Verification Method:** Start TTS/Tera/OCR/component install (or Updates check) → F8 capture hide → reopen Settings via gear → confirm installing flags are false while the worker still logs progress; click Install again; on failure, confirm phase 8 appears after reset.

### 3. `fetch_models` has no generation guard (stale dropdown wins)
- **Finding / Hypothesis:** `settings_ai.rs` `fetch_models()` spawns a thread, reads `cfg`, GETs `/models`, then `invoke_from_event_loop` unconditionally `set_ai_models` / `set_ai_local_models`. Contrast `LOCAL_MODEL_RESOURCE_WARNING_GENERATION` and `CODEX_*_UI_GENERATION` in the same file.
- **Rationale:** Open Settings (auto-fetch) → change base URL / provider / refresh quickly. The slower response overwrites the newer list and can reselect the wrong `ai_model_index`. The combobox then disagrees with `cfg` until the next save. UI lie + easy to persist the wrong id if the user clicks.
- **Verification Method:** Point cloud URL at a slow server, open Settings, immediately save a fast URL and Refresh. The first reply should not be allowed to replace the second list; today it can.

### 4. Opening Settings can write Codex config without a user gesture
- **Finding / Hypothesis:** `refresh_codex_account_status()` (called from both first-open and reuse when provider is `codex`) may `cfg.write()` + `config::save()` to fill `codex_model` / `codex_reasoning_effort`, auto-pick `codex_vision_model`, or force `vision_provider = "off"` when the catalog says the text model is not image-capable (`settings_ai.rs`, `catalog_is_authoritative` branch).
- **Rationale:** Violates “commit only on confirmed success” *and* “user confirmed”. A flaky app-server, a catalog change, or a race with `on_codex_model_selected` can persist a different model/effort or silently turn vision off (`set_vision_provider_index(0)`). Generation checks reduce but do not eliminate overlap with a user save in another tab.
- **Verification Method:** Set `ai_provider=codex`, empty `codex_model`, open Settings; confirm `config.json` now contains `gpt-5.6-luna` (or catalog default). Repeat with `vision_provider=same` and a text-only selected model; confirm disk becomes `"off"` without clicking Vision.

### 5. Systematic in-memory mutate-then-save (no rollback) — `ai_provider` is the worst
- **Finding / Hypothesis:** Invariant requires atomic commit-on-success. Almost every handler does `let mut c = cfg.write(); c.field = …; if save(&c).is_err() { return; }` and leaves the `RwLock` mutated. `on_ai_provider_changed` also runs `select_local_provider`, may set `suppress_tiles`, may rewrite `vision_provider`, then returns on save failure **without restoring**. `on_ai_prompt_cache_changed` mutates memory, skips `set_prompt_cache` on save error → memory / live static / disk three-way split. Counterexample already in-tree: `update_cloud_model()` rolls back `stt_model` and the combobox.
- **Rationale:** After a full disk / ACL failure the process keeps running on config that will vanish on restart. Provider switch is not a cosmetic field: it changes endpoints, deep-lock tile suppression, and vision. The Slint switch has already flipped; only mlx-stop failure snaps the index back.
- **Verification Method:** chmod/lock `config.json` read-only → switch AI provider, toggle prompt cache, select profile, save meeting context. Process uses the new provider; restart restores the old one. Compare with STT cloud-model combobox, which reverts.

### 6. Optimistic UI vs disk on language, tile monitor, stealth, TTS
- **Finding / Hypothesis:**
  - `on_language_selected`: `select_bundled_translation` **before** save; save error is logged only.
  - `on_tile_monitor_changed`: `set_global_tile_monitor(pin)` **before** save (comment explicitly prefers UI over disk).
  - `on_stealth_changed`: `st.stealth` + `set_global_stealth` + `c.stealth_enabled = on` with `let _ = config::save`.
  - `on_tts_voice_changed` / `on_tts_engine_changed`: combobox already moved; save failure returns without `set_voice` / `set_engine` (live sidecar ≠ UI).
- **Rationale:** Settings is the source of truth the user can see. These paths make the widget, the process global, and `config.json` diverge. Stealth is especially bad: the tab status uses `stealth_effective` after apply, but intent is already persisted in memory even if exclusion *and* save fail.
- **Verification Method:** Fail `config::save` (or inject error) while changing language / monitor / stealth / TTS voice. Confirm UI + new tiles / translation / sidecar disagree with the file on disk.

### 7. Missing Rust seeds for properties that other handlers write
- **Finding / Hypothesis:** `ai_local_model_profile_index` and `ai_local_vision_available` are set in `on_ai_provider_changed` / `on_ai_local_base_url_save` / vision toggle, **never** in `populate_token_status()`. Reuse/first-open therefore depend on Slint defaults (`0` / `false`). `context_processing` and `context_dictating` are never cleared on populate (OK if work is live; a lie if the worker already finished while Win32-hidden and the flags stuck). `server_preview_*` strings are not blanked when `server_preview_ready` is forced false; `pending_server_import` is not cleared on reopen. Hotkeys are mentioned in the `open_settings` header comment and never wired in this scope.
- **Rationale:** A managed 26B profile can open showing the 12B row; local vision can look unavailable until the user toggles provider. Dummy/default Slint values render as real state. An armed server-import `pending` after F8 is a foot-gun if Apply is still reachable.
- **Verification Method:** Configure managed quality model + local vision, restart, open Settings without touching AI provider — check profile index and vision-available. Mid `context_process` / dictate, F8 hide/show. Preview a server import, F8, inspect `server_preview_ready` vs leftover preview text / Apply.

### 8. Full-profile import can overwrite machine-local paths and dump secrets into a screen-shared line
- **Finding / Hypothesis:** `on_import_profile_clicked` loads via `config::import_from(&path, local_deep_lock)` then **replaces the entire live `SharedConfig`**. Unlike server import (`apply_server_settings` keeps this PC’s GigaAM dir), there is no host-side allowlist for `stt_gigaam_dir`, `ai_local_base_url`, `mic_device`, `tile_monitor_name`, TTS paths, or snippet/context blobs. Errors go to the UI as `format!("[err] {e:#}")`; successful **export** does `format!("[ok] exported to {}", path.display())`. Server export success also interpolates `path.display()` (errors were already genericized after audit Q8). `populate_token_status` also does `set_stt_whisper_bearer_input(c.stt_whisper_bearer.clone())` while OpenAI/Anthropic/AI bearers are deliberately blanked.
- **Rationale:** A crafted `suflyor-settings.json` (or a “backup” from another machine) can retarget local AI/STT at an attacker URL, point GigaAM at `\\evil\share` or a huge/unreadable path, blow up UI with multi-MB `meeting_context`, or toggle stealth off. Unexpected schemas depend on `import_from` (not in this diff): if it `unwrap`s or allocates unbounded, that’s a crash/DoS; if it saves then this code still clobbers runtime. Profile I/O result and Whisper bearer fields are visible on screen-share. Server two-step preview is actually careful (`mask_host`, key presence, `redact_user_home`); full-profile I/O is not.
- **Verification Method:** Import JSON with hostile `ai_local_base_url`, `stt_gigaam_dir`, huge `meeting_context`, wrong types / extra fields — watch for live endpoint change, path overwrite, parse panic, and whether disk commit is confirmed before `*cfg.write() = imported`. Export profile and confirm the result line contains `%USERPROFILE%` / username. Open STT tab with a Whisper bearer set and screen-record Settings.

### 9. Connection-test tiles still leak host/error text (except local AI)
- **Finding / Hypothesis:** Module comments claim generic test tiles. `on_ai_bridge_test_clicked` and `on_stt_test_clicked` set `format!("[err] {e:#}").chars().take(90)`. Local AI maps 503/transport to canned Russian strings. Mic test interpolates `error: {e}` and dBFS.
- **Rationale:** 90 characters of `reqwest`/`connect to http://192.168.…` is enough LAN topology for a shared Settings window. The local-AI path shows they already knew this.
- **Verification Method:** Point the cloud/STT URL at a closed port or invalid host, click Test, read the result tile (and a screen-share capture).

### 10. Empty token saves are no-ops — keys cannot be cleared from UI
- **Finding / Hypothesis:** `on_ai_bearer_save` / `on_groq_api_key_save` return on `trimmed.is_empty()` without writing. Populate only shows `[ok] set (N chars)` / `[--] not set`.
- **Rationale:** User thinks clearing the box and Save removes the key; runtime and disk keep the old secret. Opposite of optimistic flip: the widget lies toward “unset”.
- **Verification Method:** Save a Groq key, delete the field, Save, reopen Settings / inspect `config.json`.
