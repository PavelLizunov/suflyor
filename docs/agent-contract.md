# Контракт работы агентов Suflyor (docs/agent-contract.md)
**Статус:** Действующий регламент (Step 1 методологии VPNRouter)

---

## 1. Базовые принципы

1. **Скрипт впереди агента:**
   - Всё, что можно посчитать, отфильтровать или проверить детерминированно (grep, git, Python), делает скрипт.
   - Сначала показываем владельцу точные цифры скрипта, затем формулируем выводы.
2. **Параллельные рои Gemini (`gemini-flash-high-latest`):**
   - Для массового аудита и классификации задач используем инструмент `workflow` для веерного запуска субагентов по функциональным частям.
   - Координатор отвечает за сведение результатов, декомпозицию и итоговую проверку.
3. **Доказательство отделено от догадки:**
   - Каждое утверждение об исправлении или поведении сопровождается командой, номером прогона и точным SHA коммита.
   - Не заявляем «исправлено», пока нет проверки на целевой среде.
4. **Тяжёлая работа не на контроллере и не на машине владельца:**
   - Компиляция Cargo/Swift, сборка инсталляторов и нативные тесты выполняются строго на выделенных воркерах homelab (`windows-worker`, `mac-worker`) или в GitHub Actions по точному SHA через замки-каталоги.
   - На контроллере DSH компиляция и тяжёлые тесты запрещены.
5. **История Git не переписывается:**
   - Любая очистка или архивация выполняется новыми коммитами в активных ветках.
   - Старые файлы остаются в истории Git и доступны через команду `git show <sha>:путь`.
6. **Короткие структурированные отчёты:**
   - Каждый содержательный ответ начинается с обязательного блока `> **TL;DR:** <1–3 простых предложения>`.

---

## 2. Правила Git и единица работы

1. **Единица изменения:**
   - Короткий план на 5–8 строк в папке `plans/`.
   - Ветка от актуального `master` вида `codex/<short-task-name>`.
   - Точечное изменение с понятным атомарным сообщением коммита.
   - Запуск проверок на целевом воркере по точному SHA.
   - Оформление PR, прохождение CI, слияние.
   - Актуализация `DEFECTS.md` и `CURRENT_STATE.md`.
2. **Запреты без явного подтверждения владельца:**
   - Выпуск стабильной версии (только плавающие RC).
   - Удаление или перезапись тегов Git.
   - Модификация чужих активных веток.
   - Публикация секретов, токенов или персональных путей.
